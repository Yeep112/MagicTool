# Magic Tool 實驗分析

把原本 Magic Tool notebook 裡的 PPMS、SQUID、Raman、Etching Rate 分析整理成一個軟體：雙擊開啟、選檔案、調參數，圖馬上更新。
分析程式和 notebook 共用（`magic/`），軟體與 Jupyter 算出來的結果完全一樣。

```
MagicTool\
├─ install.bat          ← 第一次雙擊：建立開始功能表與桌面捷徑
├─ run_magic.bat        ← 開啟軟體（可以複製到任何地方；把檔案或資料夾拖上去會直接開啟）
├─ MagicTool.pyw        ← 直接開啟軟體（工作列釘選的圖示執行的就是它）
├─ publish.bat          ← 開發者：一鍵發佈到 GitHub（同事會收到更新）
├─ 收更新.bat           ← 開發者：收 Claude 準備好的更新（pending）→ 測試 → 發佈
├─ magic_env.bat        ← 尋找電腦上的 Python（給上面的啟動檔用）
├─ install.command      ← Mac：第一次執行，建立「Magic Tool.app」（應用程式 + 桌面）
├─ run_magic.command    ← Mac：開啟軟體 / selftest / update / publish（和 run_magic.bat 一樣）
├─ publish.command      ← Mac：開發者發佈到 GitHub
├─ 收更新.command       ← Mac：和 收更新.bat 一樣
├─ magic_env.sh         ← Mac / Linux：尋找電腦上的 Python
├─ release.json         ← 版本號與更新內容（版本號只寫在這裡）
├─ 發佈與更新.md         ← 第一次上傳 GitHub、之後每次發佈的步驟
├─ magic\               ← 程式本體（Python 原始檔，可以直接改）
│   ├─ core\            共用：設定、單位、欄位搜尋、掃描分段、Tc、峰擬合、分析登錄、結果匯出
│   ├─ readers\         讀檔：QD .dat（PPMS + SQUID 共用）、Raman 文字檔
│   ├─ ppms\  squid\  raman\  etching\     ← 每台機台一個資料夾，一個分析一個檔案
│   ├─ fab\              製程 → 樣品：步驟庫、試算表解析、資料夾掃描、樣品紀錄檔
│   └─ gui\             軟體介面
├─ notebooks\           ← 四台機台的 notebook（呼叫 magic\ 的同一份程式；上傳前自動清掉輸出）
├─ tests\               ← pytest（只用合成資料；cp950\ 模擬繁體中文 Windows 的編碼）
├─ .github\             ← GitHub Actions：推到 pending 時在真的 Windows / Mac / Linux 上跑全部測試
└─ assets\              ← 圖示
```

需要：Anaconda（numpy、scipy、pandas、matplotlib、tkinter 都內建）。Google Sheet 團隊紀錄用 Apps Script（貼「團隊設定碼」）不需要另外裝套件；用服務帳號金鑰才需要 `pip install gspread google-auth`。
Windows 和 macOS 都可以用（同一個資料夾、同一份程式）。

## 第一次使用（Windows）

1. 把整個資料夾放在固定位置，例如 `D:\Yeep\MagicTool\`（不要在 zip 裡直接執行）。
2. 雙擊 **`install.bat`**（只要一次）：「開始」功能表和桌面會出現「Magic Tool 實驗分析」。
3. 開啟後在每台機台按「選資料夾」；沒有資料想先試試看，按「先用範例資料試試看」（合成資料，不是真實量測）。
4. Etching：到 **⚙ 設定 → 蝕刻紀錄** 把「紀錄 CSV」指向原本的 `etch_rate_log.csv`。舊格式（20 欄）可以直接讀；第一次新增紀錄時會**先備份**再把新欄位加在最後面（舊欄位、舊紀錄都不變）。

## 第一次使用（Mac）

`.bat` 是 Windows 專用的，Mac 打開只會看到文字。Mac 請用 `.command` 檔：

1. 安裝 **Anaconda**（https://www.anaconda.com/download ，選 macOS；Apple 晶片 / Intel 都有）。已經有 Anaconda / Miniconda 就跳過。
2. 下載 GitHub 的 zip、解壓縮，把 `MagicTool-main` 資料夾放到固定位置（例如「文件」），不要留在「下載項目」裡一直搬動。
3. 打開「終端機」（Spotlight 搜尋 Terminal），輸入 `bash`、空一格，把資料夾裡的 **`install.command`** 拖進終端機視窗，按 Enter。
   - 這個方法一定可以執行（不受「無法驗證開發者」與執行權限影響）。安裝時會順便解除資料夾的下載隔離，之後雙擊 `.command` 也能直接開。
   - 也可以直接雙擊 `install.command`；如果出現「無法打開，因為無法驗證開發者」：
     到 **系統設定 → 隱私權與安全性**，在下面按「強制打開」（較舊的 macOS：在檔案上按右鍵 →「打開」→「打開」）。
4. 完成後「應用程式」與桌面會出現 **Magic Tool**（Launchpad、Spotlight 也找得到）。之後就從那裡開，不會出現終端機。
   開啟後在 Dock 的圖示上按右鍵 →「選項」→「保留在 Dock」。
5. 程式資料夾搬家後，再執行一次 `install.command` 即可。

Mac 上的差別：

- 設定、紀錄、log 放在 `~/Library/Application Support/MagicTool/`（Windows 是 `%LOCALAPPDATA%\MagicTool\`），下面寫 `%LOCALAPPDATA%` 的地方 Mac 都是這個資料夾。
- 快速鍵用 ⌘（⌘S 存圖、⌘E 匯出、⌘1–4 切換機台、⌘Z 復原）；紀錄表的 delete 鍵 = 刪除。
- 軟體內的「檢查更新」一樣可以用；更新後啟動檔的執行權限會自動補上。
- 找不到 Python 時，終端機會說明要裝什麼；有 Python 但缺套件時，可以選擇自動安裝。

Mac 打不開時：

- 點 App 後如果沒有正常開啟，會跳出視窗顯示錯誤的最後幾行（可以「打開紀錄」）；紀錄在
  `~/Library/Application Support/MagicTool/logs/app_launch.log`。把這個視窗截圖，或用 ⚙ 設定 → 更新 → 📦 打包錯誤紀錄 傳給維護的人。
- 在終端機執行 `bash ~/Documents/MagicTool-main/run_magic.command debug`（路徑換成你的資料夾）：
  程式直接在終端機裡開，所有訊息都會顯示出來。
- App 會先用 Anaconda 的 pythonw 開，失敗時自動改用 python 再試一次。
- **程式放在「文件 / 桌面 / 下載項目」時**：macOS 不讓從 Finder 開的 App 讀這些資料夾（從終端機可以，所以安裝時正常、點 App 卻失敗，
  錯誤是「No module named magic」）。所以 `install.command` 會把程式複製到 `~/Library/Application Support/MagicTool/program`，
  App 用那一份；下載的資料夾之後可以刪掉。軟體內的「檢查更新」也是更新那一份。
- 量測資料放在「文件」等資料夾時，第一次開啟 macOS 可能會問「是否允許 Magic Tool 取用」→ 按「好」。
  讀不到時軟體會說明到哪裡允許（系統偏好設定 → 安全性與隱私 → 隱私權 →「檔案與檔案夾」或「完整磁碟取用權」）。
- 如果提示「沒有權限讀取程式資料夾」：系統偏好設定 → 安全性與隱私 → 隱私權 →「檔案與檔案夾」允許 Magic Tool，
  或把資料夾搬到家目錄（例如 `~/MagicTool`）再執行一次 `install.command`。

- 上方切換機台（Ctrl+1～4），每台機台有自己的主色，各自記住資料夾、選的檔案、功能與參數。

- 中欄選檔案（Ctrl / Shift 多選、Ctrl+A 全選），「種類」欄會標出是 PPMS 還是 SQUID 的檔案（灰色 = 可能放錯機台）。

- 圖的大小：「固定大小」可以自己設寬高，圖不會被壓縮，放不下就出現捲軸；「填滿視窗」時每個子圖也有最小尺寸。
- **圖表樣式**（所有機台共用）：格線、X / Y 標籤、色條、刻度、圖例、標題的字體大小可以分別設定；「字體一鍵設定」小 / 中 / 大 / 特大。
- **圖例**：**拖曳**可以移到任何位置；**點一下某一項 = 隱藏 / 顯示那條資料**（疊圖比較時很方便，變淡的就是隱藏的）。

- **✎ 標題與軸標籤**：自己改圖的標題、X / Y 軸文字（空白 = 自動，「-」= 不顯示，可以用 `$...$` 寫數學式）。

  匯出結果會有 `figure.png`、表格 CSV、`result.txt` 和 `result.json`（來源檔的 SHA-256、參數、軟體版本），寫論文時可以重現。
- F5：重新計算。

## 製程 → 樣品（v0.6–v0.9）

每個樣品資料夾（例如 `…\09 TaS2 project\102`）是一個樣品，裡面「NN 步驟名稱」的子資料夾（`01 Transfer`、`05 Lithography`、`06 Lift Off`…）
是一步一步的照片與資料。樣品頁把這些整理成時間軸：

- **左**：樣品清單（篩選編號、類型、狀態；放棄的變灰；「·」= 沒有資料夾，紀錄存在這台電腦）。
- **中**：製程時間軸。`05 Lithography + 06 Lift Off` 會合成一次 contact（顯影後、鍍完的照片分別歸到子步驟）；日期從照片檔名讀。
- **右**：選一步看參數（金屬與厚度、E / S、RIE 時間、OE、hBN 厚度…）、子步驟、資料夾、照片縮圖（點一下放大）、資料檔（.dat / .txt 可以直接在 Magic Tool 開）。

第一次使用：

1. 「選資料夾」選樣品根目錄（例如 `…\00 Users\01 Yeep\00 Samples`，底下可以有專案資料夾）；「⚙ 樣品設定」填使用者名稱。
2. 「📥 從試算表匯入」：貼 Google Sheet 網址（試算表共用給服務帳號，或「知道連結的人可以檢視」），或下載成 `.xlsx` 再選檔案。
   預覽會說要建立幾個紀錄檔、有幾項需要確認；按「建立紀錄檔」後，每個樣品資料夾多一個 `<資料夾名稱>.json`（照片與試算表都不會被改）。
3. 「⚠ 待確認」逐一看對不起來的地方，雙擊跳到那一步，沒問題就「已確認」。

試算表的讀法：`marker` = 曝光對準標記、`contact` = 電極，後面的 plasma、RIE、離子研磨、鍍膜都是那一次的子步驟；
`Cr/Au_10/70 (E)` = Cr 10 nm / Au 70 nm、E = 蒸鍍、S = 濺鍍；`OE` = over etching（刻意多蝕刻的量）；`-` = 停在這裡、`N/A` = 跳過。
### 編輯（v0.7）

- 時間軸上方「＋ 新增步驟 / ✎ 編輯 / ↑ ↓ / 🗑」，或雙擊一步。contact / marker / top gate 固定有子步驟（微影、plasma、RIE、ICP、離子研磨、鍍膜、lift-off），勾有做的、參數可以不填。
- **RIE 時間建議**：hBN 厚度自動帶入前面最近的 AFM，自己填想要的 OE →「💡 建議時間」。蝕刻率用過去樣品的 RIE（(hBN + OE) ÷ 時間）中位數，沒有的話用 Etching 蝕刻紀錄。
- **⏸ 擱置**（原因、預定日期）、**✕ 放棄**（留在清單變灰，可以取消）、**✎ 結果**（低溫電阻、超導 contact、Tc）。PPMS / SQUID 分析完按「📌 寫到樣品」直接帶入 Tc 與低溫端電阻。
- **＋ 新樣品**：建立樣品資料夾與紀錄檔。
- **自動更新樣品試算表**：⚙ 樣品設定填 Apps Script 網址與通行碼（和蝕刻紀錄同一份程式，但要裝在「樣品試算表」裡，步驟見 `Google Sheet 團隊設定.md`），勾「自動更新試算表」。
  用 Label 找那一列，只寫 Status、Type、Start Time、Process、備註；沒改過的步驟照抄原本的文字；Process 格子不夠會在備註前插空白欄。

### 示意圖（v0.8）

右欄上方切到「🎞 示意圖」：上 = 剖面（依步驟自動堆疊：轉移 → marker → contact 的 RIE 窗口與金屬 → …，縱向是實際厚度），
下 = 俯視（樣品資料夾裡 digitalize 的 flake 輪廓 CSV：`graphene.csv`、`hBN.csv`、`thBN.csv`（上層 hBN）、`Ta.csv`、`contact.csv`…）。
拉桿或 ◀ ▶ 一步一步看，▶ 播放 = 動畫；點時間軸的某一步也會跳過去。轉移的堆疊在步驟編輯裡寫（例如 `hBN 20 / TaS2 / hBN 40`）。
有輪廓檔時剖面照**實際形狀**畫（v0.9.1）：沿著切線 A–A'（自動穿過兩個電極中心；「✂ 切線」在俯視圖上點兩下自己設），
電極輪廓 `contact.csv` / `contact1.csv` = Contact #1、`contact2.csv` = Contact #2、`marker.csv`、`gate.csv`。
只在雲端的照片點一下會在檔案總管打開那個資料夾，下載完縮圖自動出現。

### 一鍵匯出 PPT（v0.9）

「📤 匯出 PPT」：選一顆（單一樣品報告）或好幾顆（比較），中文 / English / 中英並列。版面沿用「樣品製程報告」模板：
封面、樣品總覽、製程流程、步驟頁（分段剖面插圖：旋塗光阻 → 曝光顯影 → RIE → 鍍膜 → Lift-off，加上 OM 照片與參數）、
AFM 厚度、電性量測、結果 / 問題 / 下一步、附錄（試算表原文對照）、多樣品比較；每一種都可以勾掉。
每顆樣品的模板（標題、哪幾步要放、給教授看的說明）存在自己的紀錄檔，下次沿用。照片會縮小再放進去；不需要另外安裝 PowerPoint 套件。

## 分析功能

| 機台 | 快速檢視 | 參數萃取 | 批次比較 |
|---|---|---|---|
| PPMS | 曲線檢視（任選兩欄、自動分段） | R–T 與 Tc | 多樣品 R–T 比較 |
| SQUID | 曲線檢視（單位自動換算） | M–T 與 Tc（ZFC / FC）、M–H 迴線 | 多樣品 M–T 比較 |
| Raman | 光譜檢視（疊圖、正規化、扣背景） | 石墨烯 G / 2D 峰、背景扣除 | 多檔峰值總表 |
| Etching | 蝕刻速率趨勢（誤差棒、▲ = 蝕穿） | 多時間線性擬合（整段 / 每段延遲）（＋ 新增紀錄 精靈） | 條件比較（平均 ± 標準差）、線寬比較（r(w) 模型擬合） |

**Tc**（PPMS、SQUID 共用 `magic/core/transition.py`）：先依掃描方向切段（降溫 / 升溫、ZFC / FC 分開），
正規化 f = (y − y_低溫) / (y_正常 − y_低溫)，從高溫往低溫找 90%、50%、10%，另外找平滑後 |dy/dT| 最大的溫度。
溫度範圍空白時自動選「最低溫到 2 × 轉變溫度」，避免 300 K 的正常態電阻把 Tc 算歪。

**Raman 峰**（`magic/core/peaks.py`）：只在指定範圍內找峰、Lorentzian 擬合求峰位 / FWHM / 高度 / 面積；
沒有明顯的峰（高度 < 5 倍雜訊、R² 太低）會回報「找不到」，不會硬給一個值。舊方法「平均強度交點寬度 Δ」也一起算，方便和以前的紀錄比較。

**Raman 工具**（參數面板下面的按鈕）

- **✎ 編修光譜**：

## 蝕刻速率（Etching）

按 **＋ 新增紀錄** 開啟精靈：左邊是製程流程（①準備樣品 → ②塗光阻 → ③曝光 → ④顯影 → ⑤蝕刻 → ⑥去光阻 → ⑦量測）的示意圖與動畫，
右邊填資料、下面即時顯示結果和**代入數字的算式**。點示意圖上的箭頭會跳到對應的欄位；點欄位，示意圖上的那段會亮起來。
不是這個領域的人也可以照著圖填。「複製條件」= 用選取那筆的材料、機台、氣體、功率開新紀錄，量測值留空。

**符號**：T = 材料蝕刻前厚度，T' = 蝕刻後剩下，T_m / T'_m = marker（Cr/Au）蝕刻前 / 後自身厚度，
H_m,out / H_out = 蝕刻後從 SiO2 表面量到 marker / 材料頂端的高度，t = 蝕刻時間（各段加總）。

| 要算的 | 量法 | 公式 |
|---|---|---|
| SiO2 | marker（預設） | d_SiO2 = H_m,out − T'_m（沒量 T'_m 就用 T_m：Cr/Au 在 SF6、CHF3 + O2 下視為不被蝕刻；有量的話會顯示 marker 被蝕刻多少） |
| | AFM 台階 | d_SiO2 = 圖案內外的台階 |
| | 橢偏儀 | d_SiO2 = h − h' |
| 材料 | 從基板量（AFM 從 SiO2 掃到樣品上） | d = T + d_SiO2 − H_out |
| | 圖案內台階 | d = S（S = T − T'） |
| 速率 | | r = d / t；選擇比 = r_材料 / r_SiO2 |

- **多點平均與誤差**：每個量測欄位都可以填好幾個點（例如 3 條 line profile：`80.1, 79.9, 80.3`），取平均 ± 標準差；
  誤差傳遞 σ_d = √(Σσ²)、σ_r = σ_d / t。單點量測誤差以 0 計，會提醒。
- **分段蝕刻**：時間填 `20+20+20`、`3x20`、`1.5min` 都可以，每一段都會記錄（`Etch steps (s)`）。
- **蝕穿偵測**：剩下 ≤ max(0.5 nm, 2σ) 判定為蝕穿 → 只能得到下限 r ≥ T / t，紀錄標記「蝕穿」，圖上畫成 ▲，平均與擬合預設排除。
- **製程參數**：材料、光阻與厚度、pattern 線寬、機台、最多 3 種氣體與流量（sccm）、ICP 與 RF 功率（沒有可以不填）、DC bias、
  壓力（Pa / mTorr / Torr / mbar，另存換算成 Pa 的值）。
- **多時間線性擬合**：同一個配方（其他參數相同）、同一個線寬，用不同時間做的紀錄擬合 d = r·t + c，斜率 = 蝕刻率、
  −c / r = 起始延遲（電漿點火、自然氧化層）。比單筆 d / t 準，也能看出延遲。
  「延遲模型」選 **每段都有延遲** → 擬合 d = r·(t − N·t₀)（N = 分段數）：每段都重新點火時用，需要不同時間或不同分段數的紀錄
  （例如 40 s 一次 和 2×20 s）；只有 1×20、2×20、3×20 這種成比例的組合分不出來，會提醒。
- **線寬比較**：只把「其他參數都相同」的紀錄放在同一條線（不同配方分開畫，並列出哪些參數不同）；
  可以除以最寬線寬的蝕刻率，看窄線寬慢多少。勾「擬合 r(w)」→ r(w) = r∞·(1 − e^(−w/w₀))，
  r∞ = 不受線寬影響的蝕刻率、w₀ = 特徵線寬（至少 3 種線寬）；「蝕刻率來源」可以選多時間擬合的斜率（扣掉延遲，比較準）。
- **⇄ 交叉檢查**：同一個樣品如果 marker 和 AFM 台階（或膜厚儀）都有量，勾選後每一種都算一次 d_SiO2，
  和主要量法比較，差超過 max(1 nm, 2σ) 會提醒；材料的「圖案內台階」和「從基板量」也一樣。結果寫進 `SiO2 cross-check` 欄位。
- **光阻蝕刻率**：① 填光阻厚度、⑦ 填蝕刻後光阻厚度 → r_光阻、材料 / 光阻選擇比、光阻最多撐幾秒；
  光阻剩不到 20%、或撐不到蝕穿整層材料的時間會提醒。
- **📈 匯入 AFM line profile**：量測欄位旁的 📈 → 選 Gwyddion「匯出文字」或 NanoScope 的 section 匯出檔（可多選、一個檔案多條），
  自動找兩個平台（同時扣掉傾斜，邊緣附近的點不用），每條 profile 一個高度，填回欄位（平均 ± 標準差）。
  邊緣有殘膠時可以改成「手動：拖曳選低 / 高的平台」。
- **📷 OM 照片（選填）**：精靈裡可以放蝕刻前、後的光學顯微鏡照片（png / jpg / tif，16 bit 也可以），點縮圖放大。
  照片複製到紀錄旁邊的 `<紀錄檔名>_images\`（檔名 = Record ID_before / _after），CSV 只記相對路徑，原始照片不動；
  換照片時舊的那張改名留著。表格的 📷 = 有照片，「🖼 OM」並排看蝕刻前 / 後。Google Sheet 只會有路徑（照片在本機）。
- **示意圖**：光阻畫成貼在樣品上的膜，材料和 marker 上方會像丘陵一樣鼓起來；有填光阻蝕刻後厚度時，蝕刻動畫裡光阻也會跟著變薄。
- **✎ 修改 / 🗑 刪除 / 🕘 修改歷史**：雙擊表格的一筆就能修改（量測值、條件都帶入）；修改前的值、刪除的紀錄都寫進
  `<紀錄檔名>.history.csv`，「修改歷史」可以還原。每筆紀錄有 `Record ID`、`Revision`、`Modified at`；
  Google Sheet 會用 Record ID 找到同一列一起修改 / 刪除（找不到時不會亂改，會請你手動處理）。
- **☁ 團隊 Google Sheet（v0.7）**：中間下拉選單選「Google Sheet」就能看所有人的紀錄（以前直接填在試算表的也可以，沒填的欄位空著），
  一樣可以畫條件比較、多時間擬合、趨勢。⚙ 設定 → 蝕刻紀錄 →「📥 貼上團隊設定碼」後，每個人新增 / 修改 / 刪除紀錄都會自動寫進同一張試算表；
  「☁ 同步」把試算表的舊紀錄加到本機 CSV，或把本機還沒上傳的補上傳。設定步驟（Apps Script、權限）見
  [`Google Sheet 團隊設定.md`](Google%20Sheet%20團隊設定.md)。

**CSV 格式（v2）**：原本 20 個欄位**順序、意義都不變**，新欄位全部加在後面（`Schema`、`Material`、`Line width (nm)`、`Gas 1`～`Flow 3 (sccm)`、
`ICP power (W)`、`RF power (W)`、`Pressure (Pa)`、`Etch steps (s)`、`SiO2 method`、`Material method`、`d_* / σ_*`、`Selectivity`、
`Etched through`、`Raw inputs`（原始輸入，JSON）、`Notes`；v0.3 再加光阻、交叉檢查、`Record ID` 等，v0.4 加 `OM before`、`OM after`）。

| 情況 | 做法 |
|---|---|
| 舊 CSV（20 欄） | 讀的時候自動換算（d_SiO2 = Δ_marker、d_材料 = Δ_hBN + Δ_marker，材料當作 hBN）；寫入前會問你，先備份成 `*.v1備份_日期.csv` 再升級 |
| 舊公式 `R_hBN = (Δ_hBN + Δ_marker) / T` | 新紀錄仍然成立（`R_hBN(nm/sec)` 欄位現在代表「選的材料」的蝕刻率） |
| Google Sheet | 用欄位**名稱**對應（大小寫、空白不計；`note` → `Notes`）：原本的欄位（含自己加的）不改、不搬，缺的加在最後面，認不得的欄位和公式不碰；新紀錄寫在最後一筆資料下面；第一列看不懂 → 不寫入；舊紀錄的 `Power` 60W、`Bias` 10V / 8W 會換算成 ICP / RF 功率與 DC bias |
| Excel 副本 | 舊標題會補上新欄位 |
| 舊版（0.2 / 0.3）寫的 CSV | 0.3、0.4 又在最後面加了 `Resist after (nm)`、`R_resist (nm/sec)`、`Selectivity (material/resist)`、`SiO2 cross-check`、`Material cross-check`、`Record ID`、`Revision`、`Modified at`、`OM before`、`OM after`：寫入時自動備份（`*.升級前備份_日期.csv`）再補上 |

## 和原本 notebook / yeep_lab 的差別

| 以前的問題 | 現在 |
|---|---|
| 降溫、升溫混在一起排序，曲線來回跳；接縫處被誤判成斜率最大 | `core/segments.py` 先切段，每段分開分析 |
| SQUID Tc = 相鄰兩點斜率最大，溫度幾乎相同的兩點會得到假的極大值 | 內插到等間距格點、可平滑後再微分；50% / 90% / 10% 用正規化數值 |
| Raman 找「最靠近 1580 / 2700 的峰」、`distance` 單位是資料點 | 在範圍內找、Lorentzian 擬合 |
| 多項式背景被峰拉高 | 只用無峰區（ModPoly）、或 ALS |
| Raman cell 用到前一格的變數（legend、標籤錯） | 每個分析是獨立的函式，不會共用變數 |
| `read_qd_dat`：Comment 欄有一格像數字就整欄變 NaN | 九成以上是數字才轉換 |
| `[Header]` 只存原始文字 | 解析成 dict（BYAPP、INFO…），用來判斷 PPMS / SQUID |
| `find_col` 有好幾個符合時默默拿第一個 | 會在文字結果提醒（例如 Bridge 1 / 2 / 3） |

| Etching：Δ_SiO2 正負號和計算相反；缺值 TypeError；負值默默改 0；重跑就重複寫入 | 統一成「被蝕刻掉的厚度」；說明缺哪一格；負值提醒；先預覽再寫入、重複會提醒 |
| CSV / xlsx / Google Sheet 三份資料 | 本機 CSV 是主要來源，Excel / Google Sheet 是選用的副本 |
| 結果 CSV 寫進原始資料夾 | 寫到輸出資料夾 |
| `paths.HOME` 依安裝方式推算、`ensure_dirs()` 在每台電腦建資料夾、金鑰放在可能同步的資料夾 | 設定、紀錄、金鑰都在 `%LOCALAPPDATA%\MagicTool\` |
